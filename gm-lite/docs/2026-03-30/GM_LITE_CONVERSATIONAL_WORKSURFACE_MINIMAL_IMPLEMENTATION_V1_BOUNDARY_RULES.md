# GM-LITE Conversational Worksurface Minimal Implementation V1 Boundary Rules

## Must Preserve

- `GM-LITE` remains a plugin worksurface, not a heavy runtime center
- `.gm_bus` remains the task-reality substrate
- `SkillForge` remains governance / audit / solidification authority
- conversational UX must not erase object visibility or evidence visibility

## Must Improve

- entry must be obvious
- high-frequency actions must be reachable inside the plugin
- recent outputs / writebacks must be visible without raw-output hunting
- prompt input must coexist with task / state / followback visibility

## Must Not Do

- do not build a generic chat clone divorced from task reality
- do not hide work inside opaque black-box transcript only
- do not route the user back to output-channel-only flows as the default path
- do not introduce new heavy runtime orchestration under UI cover

## Decision Rule

If a UI choice improves visual polish but weakens explicit task / output / action visibility, reject it.
